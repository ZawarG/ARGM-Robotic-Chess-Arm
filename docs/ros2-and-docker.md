# ROS 2 and Docker: how this project uses them

## The two-minute version

- **Your game** (`core/`) is plain Python. Run it on your Mac: `python core/main.py`. No Docker.
- **ROS 2** is a framework for splitting a robot program into small separate programs
  ("nodes") that talk by sending messages. It only installs on Linux.
- **Docker** is how we get a Linux box with ROS 2 on a Mac. It is *only* a container for
  running `ros2_ws/`. Nothing else in the repo needs it.

## ROS 2 in four words

| Word | Meaning | In this repo |
|------|---------|--------------|
| **Node** | One small program with one job | `planner_node`, `arm_node` |
| **Topic** | A named channel nodes publish to / listen on | `game/engine_move`, `arm/steps`, `arm/status` |
| **Message** | The shape of the data on a topic | `EngineMove`, `ArmPlan`, `ArmStep`, `BoardState` |
| **Package** | A folder of nodes or messages that gets built | `argm_chess`, `argm_chess_interfaces` |

## What exists today

```
(future vision node) --BoardState-->  game/board_state      (message defined, no node yet)
(future engine node) --EngineMove-->  game/engine_move
                                           |
                                      planner_node        wraps core/src/logic/move_decomposition.py
                                           |
                                      arm/steps (ArmPlan)
                                           |
                                        arm_node          dry_run=True: logs steps
                                           |               dry_run=False: core/src/hardware/robot.py -> Arduino
                                      arm/status (String)
```

Only `planner_node` and `arm_node` are written. `main.py` is **not** connected to them.

Folders:
- `ros2_ws/src/argm_chess_interfaces/msg/*.msg` : the message definitions (the "shape" of data).
- `ros2_ws/src/argm_chess/argm_chess/*_node.py` : the nodes.
- `ros2_ws/src/argm_chess/setup.py` : registers the node names (`entry_points`).
- `ros2_ws/build, install, log` : generated by `colcon build`; gitignored; safe to delete.

## Docker in four words

| Word | Meaning |
|------|---------|
| **Image** | The recipe-built Linux system (`docker/Dockerfile`: ROS 2 Jazzy + Stockfish + your pip packages) |
| **Container** | A running copy of the image. Disposable. |
| **Volume mount** | `docker-compose.yml` maps this repo to `/ws` inside the container, so edits on your Mac show up instantly in there |
| **Compose** | `docker-compose.yml`: saves the long `docker run` flags so you type short commands |

Because the repo is mounted, you edit code in VS Code on your Mac as normal, and only
*run* ROS commands inside the container.

## Everyday commands

Run from the repo root on your Mac.

Start a shell inside the Linux box (first time builds the image; it takes a few minutes):
```bash
docker compose run --rm ros2 bash
```

Inside that shell:
```bash
cd /ws/ros2_ws
colcon build --symlink-install   # compile messages + nodes; --symlink-install = .py edits apply without rebuilding
source install/setup.bash          # make the new build visible in this shell
export PYTHONPATH=/ws/core:$PYTHONPATH   # lets nodes import src.logic... from core/ (compose sets this too)

ros2 run argm_chess planner_node   # start a node (blocks; use another terminal for the next one)
ros2 run argm_chess arm_node
```

Handy inspection commands (any shell with the build sourced):
```bash
ros2 node list                         # which nodes are running
ros2 topic list                        # which topics exist
ros2 topic echo arm/steps              # print every message on a topic
ros2 interface show argm_chess_interfaces/msg/EngineMove   # see a message's fields
```

Send a test move by hand (white pawn takes on d5):
```bash
ros2 topic pub --once game/engine_move argm_chess_interfaces/msg/EngineMove \
  "{fen: 'rnbqkbnr/ppp1pppp/8/3p4/4P3/8/PPPP1PPP/RNBQKBNR w KQkq - 0 2', uci_move: 'e4d5'}"
```
`arm_node` logs `step 1/2: d5 -> bin` then `step 2/2: e4 -> d5`.

Leave the container with `exit`. It is deleted (`--rm`); your files are safe because they live
on your Mac.

## Rules of thumb

- Editing a node's `.py` file: just restart the node (with `--symlink-install`; without it, re-run `colcon build`).
- Editing a `.msg` file or `setup.py`: re-run `colcon build`, then `source install/setup.bash`.
- Rebuild the Docker *image* (`docker compose build`) only when `docker/Dockerfile` or
  `core/requirements.txt` changes.
- Something weird in ROS? Delete `ros2_ws/build install log` and rebuild.
- Docker on macOS cannot see USB/serial ports, so the real Arduino cannot be used from the
  container. That is why `arm_node` defaults to `dry_run=True`. For hardware, either run the
  node on a Linux machine/Raspberry Pi, or keep using `core/src/hardware/robot.py` natively.
